La règle du jeu

Trois étapes, toujours dans cet ordre. Les indices s'ouvrent un par un, jamais tous d'un coup, et ils ne citent aucune phrase de la solution officielle.

1

Chercher vraiment

L'énoncé est rendu en KaTeX (police mathématique embarquée, utilisable hors ligne). Trois paliers d'indices : stratégie générale, technique repérée dans la solution, puis liste de contrôle avant rédaction.

2

Rédiger

Un espace Markdown/LaTeX, comme une copie : étapes clés, cas limites, cas d'égalité, conclusion. La progression est enregistrée par compte.

3

Faire corriger

La rédaction part au correcteur IA, qui la compare à la solution officielle et répond en JSON strict. Verdict positif : la solution se débloque et l'historique conserve la correction.

Ceci est une vitrine statique. Netlify ne peut pas exécuter Django : sans serveur, il n'y a ni verrou, ni appel au correcteur, ni base de progression. Les formulaires de ces aperçus sont donc désactivés — c'est annoncé au clic, et non laissé en erreur 405.

Le verrou IA, dans le détail

L'endpoint POST /api/problems/<id>/verify suit quatre étapes : lecture de la solution officielle en base, réception de la rédaction, appel au modèle avec ce prompt système (celui du cahier des charges, verbatim), puis analyse du JSON renvoyé.

Rôle : Tu es un correcteur expert des Olympiades Internationales de Mathématiques (IMO).
Tâche : Évaluer si le plan de solution ou la preuve soumis contient une logique mathématique valide et arrive au bon résultat par rapport à la solution officielle.
Données : Énoncé={statement}, Solution officielle={official_tex}, Soumission étudiant={user_submission}.
Réponds UNIQUEMENT en JSON strict sans balises markdown :
{"passed": true ou false, "feedback": "2-3 phrases explicatives."}

Verdict positif

  • is_solved = true, unlocked_at = maintenant
  • la soumission passe en PASSED
  • la réponse renvoie success: true, unlocked: true, puis la page suivante sert la solution officielle, sa réponse compacte et l'historique

Verdict négatif

  • la soumission est archivée en REJECTED avec la correction
  • success: true, unlocked: false — un refus est une réponse, pas une panne
  • la solution reste hors de la page : un test le vérifie sur les 4 332 fiches verrouillées

Héberger la vraie plateforme

Le code est un projet Django standard (SQLite en développement, PostgreSQL en production) : n'importe quel hébergeur Python convient. Le dépôt contient déjà Dockerfile, deploy/render.yaml et settings_production.py.

Ce qui doit tourner côté serveur

  • la clé du correcteur IA (jamais dans le navigateur)
  • la solution officielle, servie uniquement après déblocage
  • la progression et l'historique des soumissions
  • la session et l'inscription fermée

Netlify sait faire quoi, ici

  • servir cette vitrine (statique, rapide, HTTPS, en-têtes de sécurité)
  • héberger une fonction serverless — mais l'application devrait alors être réécrite pour un autre modèle d'exécution
  • pas de Django, pas de base de données, pas de verrou côté serveur
Hôte recommandé pour la vraie application : Render, Railway, Fly.io ou PythonAnywhere (Docker ou WSGI), avec PostgreSQL et les variables DJANGO_SETTINGS_MODULE=config.settings_production, DJANGO_SECRET_KEY, DJANGO_ALLOWED_HOSTS, GEMINI_API_KEY. La procédure complète est dans docs/PUBLIER.md.
